# Memory

How guest memory is managed, how it reaches Vulkan and comes back, how guest writes are detected, and what each event costs by reading the code. Paths below are repository-relative; short forms used in tables: `HG/` = `src/graphics/host_gpu/`, `RC/` = `src/graphics/host_gpu/renderer/cache/`, `R/` = `src/graphics/host_gpu/renderer/`. Nothing here is a measurement; the only numbers are constants in code or arithmetic on them (marked "derived"). Measured results are in [OPTIMIZATION_LOG.md](OPTIMIZATION_LOG.md). Thread and lock overview: [THREADING.md](THREADING.md).

## Guest address space and kernel memory calls

Facts:
- Guest memory is the real host memory of the process: guest code reads and writes it natively. It is a committed mapping of a backing store (Windows file mapping, Linux shared memfd) with a second, never-protected "backing view" of the same bytes (`m_backing_base`) (`src/kernel/memoryAddressSpace.inc:28-92`). Reads through the backing view need no lock and cannot fault (`TryReadBacking`, `:173-181`, comment `:186-187`).
- Constants: 12.5 GiB budget, 64 MiB reserved cache, 64 MiB included table memory, 4 KiB page tables mapping 2 MiB regions, default flexible size 448 MiB (`src/kernel/memory.cpp:57-71`).
- Initialisation reads content memory parameters, adds trinity-mode memory when applicable, subtracts table overhead and creates the address space and the physical, flexible, pooled and virtual-range managers (`src/kernel/memory.cpp:1025-1051`). Physical, flexible and pooled allocators use `std::map` free lists and mappings (`:645-763`).
- Locks: a recursive `g_memory_operation_mutex` guards whole operations; a shared `g_memory_state_mutex` protects state only during changes, never across graphics calls or guest memory accesses (`:177-181`). Runtime allocation aligns to 16 KiB guest pages, finds a free range and commits it under both locks (`:2903-2924`); protect, free and `KernelMprotect` follow the same pattern (`:2985-3025`, `:3070-3074`).
- Mapping and unmapping notify `RenderContext::MapMemory`/`UnmapMemory` for GPU address ranges (`:87-109`). `InstallGpuResources()` installs walker hooks and reads GPU tables through the buffer cache on the GPU thread (`:911-939`).
- `UnmapMemory` drains the GPU when a registered buffer/texture range or a pending priority operation overlaps (`R/renderContext.cpp:146`); a port of an upstream change limits the drain to the touched range ([OPTIMIZATION_LOG.md](OPTIMIZATION_LOG.md), 2026-11-19).
- Protection calls from the trackers go `PageManager::Protect` → `LibKernel::Memory::ProtectGuestHostMemory` (`src/kernel/memory.cpp:3008`) → `GuestAddressSpace::ProtectTransient` (`memoryAddressSpace.inc:633`, shared `g_memory_state_mutex`) → `ProtectMappedUnlocked` (`:804-822`, one OS call per mapped region overlapped) → `VirtualProtect` (`src/common/platform/sysWindowsVirtual.cpp:73`) or `mprotect` (`sysLinuxVirtual.cpp:57`). A failed call is fatal (`HG/pageManager.cpp:195`).
- `hostMemory.cpp` answers "is this range readable" through `VirtualQuery` or `/proc/self/maps` (`HG/hostMemory.cpp:211-268`).
- Writes by the GPU side into private mappings outside the backing go through `PageManager::WriteGuest` (make RW, memcpy, restore protection; `HG/pageManager.cpp:335-371`).

## How guest memory reaches Vulkan and comes back

All paths are GPU-thread driven unless noted. Sizes fixed at construction: staging 512 MiB, stream 64 MiB, download 64 MiB, device 128 MiB (`RC/bufferCache.cpp:279-282`), GDS 64 KiB (`:49`).

| Direction | Path | Copies |
|---|---|---|
| Guest → buffer (vertex/index/constant/storage) | `BufferCache::ObtainBuffer` → `SynchronizeBuffer` → `UploadCopies` (`RC/bufferCache.cpp:512-625`) | guest page → mapped staging ring (`m_staging_buffer`, `MemoryUsage::Upload`, `:279`) by CPU memcpy (`CopySparseMemory`/`CopyGuestForUpload`) → `vkCmdCopyBuffer` into the per-range device-local cache buffer (`:495-497`). Dirty pages only, in runs. |
| Guest → buffer, small CPU-written range | stream-copy path of `ObtainBuffer` (`:695-719`) | memcpy straight into the 64 MiB `m_stream_buffer` (device-preferred, host-visible); the draw binds the ring slot; no cache buffer, no tracker change |
| Guest → shader by address (BDA) | `SynchronizeBda` (`:1801-1884`) | staging → cache buffer for CPU-dirty pages inside existing cache buffers; shaders find a buffer through the BDA page-table buffer (device-local, 8 bytes per 16 KiB page, `CACHING_PAGEBITS=14`, `RC/bufferCache.h:37-41`; derived: `CACHING_NUMPAGES = (2^40 + 512 GiB) >> 14 = 100,663,296`, table 768 MiB, plus a 12 MiB fault bit buffer, `RC/faultManager.cpp:29-30`) |
| Guest → texture | `TextureCache::InitializeImage` → `UploadImage` (`RC/textureCache.cpp:1012-1033`, `:950-1010`) | (a) a cache buffer exists over the image: `SynchronizeBuffer`, then detile from it; (b) none and the range is not GPU-modified: whole image bytes memcpy'd from the backing view into staging (`ObtainBufferForImage`, `RC/bufferCache.cpp:798-819`), no tracker involved; then compute detile into a scratch buffer, then `vkCmdCopyBufferToImage` (`R/image/image.cpp:250-285`). Linear images skip the compute step (`R/image/tiler.cpp:316-322`). |
| Buffer → guest (GPU-written) | `DownloadBufferMemory` (`RC/bufferCache.cpp:185-270`), `RecordEagerBatch` (`:1259-1398`) | `vkCmdCopyBuffer` cache buffer → `m_download_buffer` (64 MiB, host-random-access), then a priority operation memcpy into the backing store (`TryWriteBacking`) or `PageManager::WriteGuest` |
| Image → guest | `DownloadImageMemory` (`RC/textureCache.cpp:1899-1970`), `BcAlias::Publish` (`:747-771`), `SynchronizeBufferFromImage` (`:1851-1897`) | image download (tile compute if tiled, `R/image/tiler.cpp:339-350`) into a buffer, then the same publication. `readback_linear_images`, `readback_tiled_images`, `readback_storage_images` default to false (`src/common/emulatorConfig.h:99-101`, read at `textureCache.cpp:~127-129`), so by default render targets are not written back. Written back anyway: GC under memory pressure (`:2272`), block-compressed alias retirement (`BcAlias::Resolve`, `:773-791`), a texel-buffer binding reading a GPU-written image (`SynchronizeBuffer` with `is_texel_buffer && !is_written`, `RC/bufferCache.cpp:527-529`) |
| GPU-ordered CP write | `WriteInGpuOrder` (`RC/bufferCache.cpp:887-910`) | `vkCmdUpdateBuffer` (≤ 64 KiB) into the cache buffer in command order instead of a CPU write |

Image page watching is separate from the buffer tracker: images call `PageManager::UpdatePageWatchers<true>` on their whole range (`RC/textureCache.cpp:336-358`) and keep their own CPU/GPU state flags on `Image` (`R/image/image.h:74-114`, `:177-180`).

## Write detection

### Granularity and API

- Tracker page 4 KiB, tracker region 4 MiB (1024 pages), tracked address space 2^44 (`HG/regionDefinitions.h:12-16`). The host page size must be 4 KiB or the process exits (`HG/pageManager.cpp:140-158`).
- `PageManager` keeps two 8-bit counters per page, `write_watchers` and `access_watchers` (`:81-83`). Protection is derived: any access watcher → no access; else any write watcher → read-only; else read/write (`:85-93`). Counter overflow/underflow is fatal (exit code 322; `:41-50`, `:99-125`).
- `UpdateRegionWatchers` (`:200-261`) walks the pages of a region under the PageManager region spin flag and coalesces runs with identical new protection into one OS call. With `defer=true` it only counts and records `pending` bits; `FlushDeferred` (`:263-309`) issues the calls later (used only when `KYTY_X_CUT_ON` contains `g`, see [Deferred protection](#deferred-protection-off-by-default)).
- Both caches add watchers on the same counters: the buffer tracker (CPU-clean pages: write watch; GPU-dirty pages: access watch = no access) and the texture cache (write watch over the image range; read watch only while a storage write-back is pending, `RC/textureCache.cpp:1951`).

### Tracker data structures

- `MemoryTracker` (`HG/memoryTracker.h`): `m_regions` = 4,194,304 atomic pointers (derived 2^44 / 4 MiB, allocated at construction, `HG/memoryTracker.cpp:11`) to lazily created `RegionManager`s (`:54-68`). Queries on a missing region read as "not modified"; `IsRegionCpuModified` uses `Iterate<true>` and creates regions (`:72-76`).
- `RegionManager` (`HG/regionManager.h`): per 4 MiB region, `RegionBits` (1024 bits = 128 B, `regionDefinitions.h:35`) `m_cpu_dirty` (starts all set, `regionManager.h:129`), `m_gpu_dirty`, `m_rewritten`, `m_hot`, `m_hot_fresh`, `m_exact_hot` (`:634-647`); a spin lock (`TrackingSpinLock`, `:35-81`: busy-wait with `_mm_pause`, owner id stored, re-entry by the same thread is a hard exit); an atomic `m_generation` bumped on every state change (`:136-138`, `:485`); an optional `PageHistory` (frame/streak/slot per page, ~5 KiB) created on the first write fault in the region when exact hot pages are on (`:490-499`).
- Meaning: CPU-dirty page = not write-watched, GPU copy stale; CPU-clean = write-watched. GPU-dirty page = access-watched (no access), newest bytes live in a cache buffer (`ChangeState`, `:186-261`). Setting CPU-dirty with a GPU-dirty bit set is an `EXIT` (`:192-194`).
- Exact byte-level GPU-written ranges are kept by the buffer cache in `m_gpu_modified_ranges`, a `RangeSet` (`std::map` of [begin, end) plus a 32-slot "recent" cache that answers repeated identical `Add/Contains/Intersects` without a tree walk, `HG/rangeSet.h:15-196`). `Removals()` is a counter used by memos (`:74-76`). `RangeSet` has no lock; users are GPU-thread-only or guarded by `m_bda_sync_mutex`.
- Generations: `RegionGenerations(vaddr, size)` = sum of the touched regions' generations, 0 if a region does not exist or holds an exact hot page (`memoryTracker.h:335-352`). Two memos use it: a thread-local 4096-slot direct-mapped `UploadMemo` in `ForEachUploadRange` (`:308-329`, `:168-182`) and `ObtainMemo` (2048 slots) in `ObtainBuffer` (`RC/bufferCache.h:284-309`).

### From a guest write fault to the resumed instruction

1. **Exception.** Windows: `AddVectoredExceptionHandler(0, ...)`; `ExceptionFilter` runs on the faulting guest thread and returns `EXCEPTION_CONTINUE_EXECUTION` when handled, which retries the instruction (`src/common/hostException.cpp:97-147`, `:237`). Linux: `sigaction` with `SA_SIGINFO | SA_RESTART | SA_ONSTACK` on a per-thread alternate stack (`:242-245`). See [CPU.md](CPU.md#host-exception-path).
2. **Dispatch.** `KytyExceptionHandler` (`src/loader/runtimeLinker.cpp:625`): illegal instruction → emulator; access violation → SRT walker check (`:640-681`), otherwise `Memory::HandleGpuFault` (`src/kernel/memory.cpp:942`) → `RenderContext::HandleFault` (`R/renderContext.cpp:65-84`), `GpuFaults` counter bumped.
3. **HandleFault.** The host reports only the faulting byte, so size is 1 and one 4 KiB tracker page is resolved per fault (`:66-70`). Steps: `IsMapped` (shared `m_mapped_ranges_mutex` + `RangeSet::Contains`, `:114-120`); `WaitWriteBacks` (`:86-98`; returns at once unless `readback_storage_images`, `textureCache.cpp:1972-1975`); for a write: `BufferCache::InvalidateMemory`, `TextureCache::InvalidateMemory`, `ImageHeap::InvalidateMemory` (not read); for a read: `BufferCache::ReadMemory`.
4. **Buffer side.** `BufferCache::InvalidateMemory` (`RC/bufferCache.cpp:340-344`) → `MemoryTracker::InvalidateRegion` (`memoryTracker.h:107-126`): per existing region take the spin lock; if the page is GPU-dirty release and run `ReadMemory(.., is_write=true)` (step 7); else `ChangeState<Cpu,true>`: set CPU-dirty bit, `NoteWriteCycles` (exact-hot streak bookkeeping), unwatch the page (one `VirtualProtect` through `UpdatePageWatchersForRegion`, `regionManager.h:248-250`, `:589-594`), bump the generation. Then `QueueBdaSync(vaddr, size, true)` (`bufferCache.cpp:1613-1645`): `m_bda_sync_mutex`, `RangeSet::Add` of the page, atomic flag.
5. **Texture side.** `TextureCache::InvalidateMemory` (`RC/textureCache.cpp:2136-2168`): lock-free pre-check `m_registered_pages.Any(...)` (per-1 MiB-page atomic counters) returns at once when no image is registered on the pages (`:2142-2146`); otherwise takes `m_lock` (spin) and for each image on those pages: overlapping the written bytes → `MarkCpuDirty` + `UntrackImage` (all of the image's pages lose their watch); only sharing a page → head/tail untrack or `MarkAsMaybeDirty` (a hash of the image's first/last partial-page bytes is taken now and compared at next use, `:331-334`, `R/image/image.h:83-93`, `image.cpp:730-745`).
6. **Resume.** The instruction retries and writes; the page is now writable. Per fault: one exception round trip, one or more `VirtualProtect`, a few atomics/maps. The next GPU use of the page re-watches it (another `VirtualProtect`, `ForEachModifiedRange`, `regionManager.h:334-343`) and copies it. Code comments state the same economics: "a fault and two protection changes per frame" (`HG/hotPages.h:170-171`), "saves a fault and two protection changes per write" (`regionManager.h:222-225`).
7. **Read (or write) of a GPU-dirty page** (no access): `BufferCache::ReadMemory` (`RC/bufferCache.cpp:346-404`) calls `GuestGpu::SendCommandSync` (`src/graphics/guest_gpu/graphicsRun.cpp:105-117`): a closure is queued to the GPU thread and the guest thread blocks on a semaphore. The GPU thread runs queued commands between PM4 packets (`ProcessCommands` at the top of each packet loop, `:665`; after `FlushDeferredTracking`, `:86-91`). The closure completes eager downloads in a 512 KiB-aligned window (`DownloadWindowSize`, `bufferCache.cpp:51`, `:365-369`), then if still GPU-modified runs `DownloadBufferMemory<false>` of the window (clamped to the buffer): copy recorded, `Wait(tick)` on the GPU timeline plus `WaitPriorityOperations`, publish into guest memory (`:264-267`), then `UnmarkRegionAsGpuModified` (access restored). Small (≤ 16 pages) faulting reads also add pages to `m_readback_pages`, so later GPU writes there are downloaded eagerly at batch submission (`:371-379`; `RecordEagerDownloads` is called from `CommandScheduler::Flush`, `R/commandScheduler.cpp:165`).

### Hot and rewritten pages that stop being watched

Two separate mechanisms.

- **Sticky / "rewritten" pages**: only with `KYTY_STICKY_PAGES=1`; default off (`HG/regionManager.h:89-92`; the comment records a title that wrote such pages after submission while compute read stale bytes). A page written again after upload stays unwatched and is re-uploaded once per submission epoch (`:224-239`, `:294-332`); lifetime `KYTY_REWRITTEN_FRAMES` (default 64, `:623-630`). Unwatched pages are re-detected per submission by `ScanUnwatchedPages` (`RC/bufferCache.cpp:1647-1743`), which hashes each page with XXH3 (up to 4 threads via `std::async` when ≥ 4 MiB is unwatched, `:1673`, `:1695-1719`; `KYTY_BDA_HASH=0` disables hashing).
- **Exact hot pages** (`KYTY_X_CUT` letter `e`, on by default, but enabled only when the host view is not active, `bufferCache.cpp:296-303`): a page that took a write fault in `HOT_STREAK=3` consecutive frames (frame counter `AdvanceTrackerFrame`, `src/graphics/presentation/videoOut.cpp:910`) becomes hot: it stays CPU-dirty and unwatched, a 4 KiB shadow slot (1024 slots = 4 MiB, `hotPages.h:30`) keeps the bytes of its last upload, and "is it modified" is answered by `memcmp` against the shadow (`HotPages::Changed`, `:99-115`; `RegionManager::IsModified`, `regionManager.h:146-158`). Uploads of hot pages copy through the shadow (`CopyGuestForUpload`, `bufferCache.cpp:1767-1799`). Demotion: unchanged for `HOT_IDLE_FRAMES=8` (`memoryTracker.h:389`, `:61`) or when the frame's compares exceed 1024 + 24 per live page (`KYTY_HOT_COMPARES`, `hotPages.h:173-189`), which also suspends promotion for 64 frames (`:186`). `ScanHotPages` runs at each `SynchronizeBda` (`memoryTracker.h:42-72`).
- Hashing: XXH3 is used for unwatched-page change detection (sticky mode) and for image edge pages; exact hot pages use `memcmp`.

### Deferred protection (off by default)

`CutEnabled('g')` is true only if `KYTY_X_CUT_ON` contains `g` (`HG/cutSwitch.h:26-33`) and the host view is off (`RC/bufferCache.cpp:306-308`). Then BDA re-watch and GPU-dirty protections plus the upload bytes behind them are applied by `FlushDeferredTracking` (`:533-549`) before the batch is submitted (`R/commandScheduler.cpp:503`, `:544`), before any non-draw PM4 packet (`graphicsRun.cpp:702`, `PacketKeepsGuestMemory` `:629-660`) and before queued commands (`:86-91`). Comment at `cutSwitch.h:19-22`: off by default because other watchers can then miss a write-back. A measured crash with this cut on: [OPTIMIZATION_LOG.md](OPTIMIZATION_LOG.md), 2026-11-23.

## Buffer cache

### Structures

`m_slot_buffers` (SlotVector), `m_buffers` (`std::map` start address → id, non-overlapping), `m_page_table` = `MultiLevelPageTable<BufferId,14,44,20>` (16 KiB page → owning buffer id, lazily allocated 1024-entry buckets, `RC/bufferCache.h:174`, `:200`; `RC/multiLevelPageTable.h:16-82`), `m_lru_cache` by GC tick. A buffer is one device-local `vk::Buffer` with all usage flags and a device address (`CreateBuffer`, `bufferCache.cpp:495-497`) and carries `last_read_tick`, `last_write_tick`, `stream_score` (`streamBuffer.h:75-79`). No mutex protects these; the comment at `bufferCache.h:101` says GPU-thread serialisation.

### ObtainBuffer(vaddr, size, is_written, is_texel, id) (`RC/bufferCache.cpp:638-764`)

1. If written: `ForgetCpKnownWords` (cheap atomic bounds test first, `:964-984`).
2. **Memo hit test**, only when `CutEnabled('a')` (default on), not a texel read, not sticky mode and the host view inactive (`:655-657`): slot by hash of (vaddr, size, written) in a 2048-entry array; hit if `m_obtain_state`, size, written, `RegionGenerations` and (for written) `m_gpu_modified_ranges` removals/containment match (`:666-671`). A hit does `TouchBuffer`, sets ticks, (written) refreshes removals and maybe redoes `NoteReadbackWrite`, and returns `{buffer, offset}` (`:672-691`). `m_obtain_state` grows (`InvalidateObtainMemos`) on every buffer register/unregister (`:140`), colour-metadata check add (`:1032`), read-back page add (`:377`), GPU bytes leaving `m_gpu_modified_ranges` (`:205-207` unless letter `i`), `AdoptGuestMemory` (`:1052`).
3. **Stream-copy path**: not written, size ≤ 16 KiB, page not GPU-modified and CPU-dirty (`:695-697`): look up a 1024-slot table by address hash; reuse the previous ring copy if same range, same draw window (`m_draw_window`, bumped by every PM4 op not flagged `g_cp_op_keeps_draw_window`, `graphicsRun.cpp:721-723`), same scheduler tick and the ring advanced ≤ 1/8 of its size (`:701-707`). Else `m_stream_buffer.Map(size, alignment, allow_wait=false)` and memcpy from guest (`:708-717`); when the ring cannot map without waiting it falls through to the buffer path. This path never clears the CPU-dirty bit nor re-watches, so a range served this way stays unwatched and is re-copied once per draw window.
4. **Buffer path**: `FindBuffer` (`:406-422`; page-table lookup of the first page, bounds check, else `CreateBuffer`). `TouchBuffer`, tick, `SynchronizeBuffer` → `MemoryTracker::ForEachUploadRange`. Written: `m_gpu_modified_ranges.Add`, `ForgetColorMetadataChecks` (8 RangeSets), `NoteReadbackWrite` (`:766-796`; queues eager downloads and names the writer program for pages in `m_readback_pages`). Host view adds `m_gpu_owned` + `WriteBdaEntries` (`:729-742`). Finally the memo is stored (`:749-762`).

### ForEachUploadRange (`HG/memoryTracker.h:157-229`)

Own memo first. Otherwise per region (`Iterate<true>`, creates regions): read-only calls skip a region without lock if nothing in range is CPU-dirty; else lock and `ForEachModifiedRange<Cpu,true>`: clears the dirty bits and **re-watches the pages (VirtualProtect) before** reporting them, so a guest write after the re-watch faults again and one before it is in the copy (`regionManager.h:334-346`; comment `memoryTracker.h:233-236`). The callback collects `vk::BufferCopy`s; `upload_func` → `UploadCopies`. For written ranges the region lock is taken (`:196`) and **kept until after `upload_func` and the GPU-dirty marking** (`:210-218`): the copy into staging runs under the region spin lock, and `UploadMemory` → `StreamBuffer::Map` with `allow_wait` default true may wait for the GPU (`RC/streamBuffer.cpp:325-345`) while holding it. Then `ChangeState<Gpu,true>` (access watch, no access) on the whole range.

### Creation, merging, eviction

- `CreateBuffer` (`bufferCache.cpp:488-510`): range widened to 16 KiB pages; `ResolveOverlaps` (`:424-475`) takes the union of every overlapping buffer; if the overlapped buffers' summed stream score exceeds 16 the new buffer is extended by 128 pages (2 MiB) in the direction of growth. A new device-local buffer of the union size is created; every old buffer is GPU-copied into it (`JoinOverlap` → `Buffer::CopyFrom`, two barrier pairs, `streamBuffer.cpp:150-179`) and deleted (deferred until its tick is done, `bufferCache.cpp:176-183`); `Register` fills the page table (`:116-170`) and writes BDA entries via `WriteDataBuffer` (staging copy + 2 barriers + copy, `:75-114`), then `QueueBdaSync(whole buffer)`. Buffers only grow by merging; nothing splits them. `m_bda_hash_generation` is bumped (`:489`).
- `RunGarbageCollector` (`:1556-1607`) runs once per frame at the suspend point (`graphicsRun.cpp:578` → `renderContext.cpp:175-186`): acts only if device memory use ≥ trigger (1 GiB until the `BufferCache` constructor computes it from the device-memory budget when the device can report it, never below 1 GiB; `bufferCache.cpp:309-320`, `bufferCache.h:400`); age ≥ 160 ticks (80 when use ≥ critical, computed the same way, never below 2 GiB); at most 32 (64) buffers; GPU-dirty buffers are skipped unless critical, in which case they are downloaded and the GPU thread **waits** (`m_scheduler.Wait`, `:1598-1599`). Clean buffers are marked CPU-dirty (unwatched) and deleted.

### BDA page table, fault buffer and host view

- Shaders using addresses read `m_bda_pagetable_buffer[page]` for a device address. Entries are written on `Register`/`Unregister` (`bufferCache.cpp:116-170`). For pages with no buffer, the shader records the page in the fault bit buffer; `FaultManager::ProcessFaultBuffer` (`RC/faultManager.cpp:68-142`; called from `RenderContext::RunGarbageCollector` only when a BDA draw happened since, `renderContext.cpp:165-179`) dispatches a compute pass over the whole bit buffer (derived: `CACHING_NUMPAGES/128` threads = 786,432, 12,288 workgroups of 64, `faultManager.cpp:115-117`), copies the results to a download ring of 8 areas, and in a deferred operation calls `FindBuffer` for each reported range (creating buffers). It waits for the area's older tick if all 8 are in flight (`:69-72`).
- `PrepareBda` (`renderContext.cpp:165-172`; called from `descriptors.cpp:1204` and `renderCompute.cpp:456`, `:700` for DMA shaders) holds `m_mapped_ranges_mutex` shared while `SynchronizeBda` (`bufferCache.cpp:1801-1884`) runs: drains `m_bda_sync` (pages queued by write faults, new mappings, new buffers), intersects with mapped ranges and existing buffers, then `ForEachUploadRangeBatch` (one protection change per tracker region, `memoryTracker.h:237-291`) and one `UploadCopies` for everything. So every guest write to a page covered by a cache buffer causes one fault, one queued range and (when a DMA shader runs) a re-upload of that page, whether or not any draw reads it.
- Scalar/draw pre-caching: every draw/dispatch backs 3 cache pages after each scalar-loaded base (`CacheDmaBases`, `BackDrawAddressBases`, `FindBuffer(page,1)` each) so loads of uncached pages do not read zero (`R/descriptors.cpp:1176`, `R/renderCompute.cpp:239`).
- **Host view** (`InitHostView`, `bufferCache.cpp:1886-1918`): when active, the page table points CPU-clean pages at imported 32 MiB chunks of the guest backing (`HostAddress`, `:1929-2011`, needs `VK_EXT_external_memory_host` and an aligned backing) so shaders read guest memory directly; GPU-written pages point at the cache buffer (`m_gpu_owned`); exact hot pages, deferred protection and the `ObtainBuffer` memo are all off in that mode (`:300`, `:306`, `:657`). Entries are diffed against `m_pt_shadow` and written in sorted runs by `FlushBdaEntries` (`:2013-2098`).
  - **Default state, settled from source.** One study read the host view as wanted by default when `KYTY_GPU_SRT` is unset; the source says otherwise. The code: `InitHostView` returns at once unless `GpuSrtHostViewWanted()` (`:1887`). `GpuSrtHostViewWanted()` = `GpuSrtMask() != 0 && (!GpuSrtAuto() || g_runtime_learning)` (`src/graphics/shader/recompiler/ir/passes/ResourceTracking.cpp:92-95`). With `KYTY_GPU_SRT` unset, mask = `GpuSrtDefaultParts | GpuSrtAutoParts` (nonzero) and learning = true (`:38-48`), but the `CommandScheduler` constructor calls `SetRuntimeLearning(false)` (`R/commandScheduler.cpp:92`), which clears `g_runtime_learning` (`ResourceTracking.cpp:177`). Result: the host view is **not** wanted in the default configuration of this tree, so exact hot pages, the `ObtainBuffer` memo and (if requested) deferred protection are in their enabled/available state. `KYTY_GPU_SRT=0` gives mask 0, also not wanted; any other value gives the same as unset (`:44-47`).

### Downloads, read-backs and when the GPU thread waits

GPU-thread waits found: sync `DownloadBufferMemory<false>` (`bufferCache.cpp:264-267`; from `ReadMemory` and `ReadTable`); `CompleteEagerDownloads` (`:1451`, `:1456`, `:1491`); `StreamBuffer` ring wrap (`streamBuffer.cpp:337`); `FaultManager` area reuse (`faultManager.cpp:69-72`); buffer GC at critical (`bufferCache.cpp:1598`); texture GC download (`textureCache.cpp:2304`); `UnmapMemory` drain (`renderContext.cpp:~140-146`); `WaitWriteBacks` (storage read-back only). Guest-thread waits: the `SendCommandSync` semaphore (`graphicsRun.cpp:111-116`) and spins on region/texture locks. Complete list with the other areas: [THREADING.md](THREADING.md#where-threads-wait).

Eager downloads: pages that were once CPU-read while GPU-dirty are downloaded in one batch at every `CommandScheduler::Flush` (`RecordEagerDownloads`, `bufferCache.cpp:1243-1254`) and released when their tick finishes (`CompleteEagerDownloads`, `:1401-1546`), which keeps the pages protected until publication ran. Early-compute learning (`NoteProducerWait`, `:1148-1169`; constants in code: 20 waits and 20 ms within 2 s) uses these waits ([GPU.md](GPU.md) owns early compute).

## CP-known overlay and GPU-ordered writes

`WriteInGpuOrder` (`bufferCache.cpp:887-910`) applies only on the GPU thread, dword aligned, ≤ 64 KiB, over GPU-modified, registered, non-write-back pages. It records `vkCmdUpdateBuffer`, invalidates images over the bytes (`InvalidateMemoryFromGpuOrderedWrite`, `textureCache.cpp:2000-2014`) and stores the words in `m_cp_known` (`std::map<addr,u32>`, limit 65536 words, `m_cp_known_mutex`; `bufferCache.cpp:912-931`). `NoteCpKnown`/`NoteCpFill` (`:933-949`) store CP fills/copies ≤ 4096 B on GPU-modified ranges. Readers (`TryCurrentWalkerLoad` `:1087`, `ReadTable` `:1116`, `KnownBytes` `:951`) answer from the overlay, or from guest memory when no GPU write covers the bytes, avoiding a read-back. A written `ObtainBuffer` drops overlapping known words (letter `h` adds a bounds early-out). The CP side that calls this (WRITE_DATA, RELEASE_MEM) is in [GPU.md](GPU.md).

## Texture cache

- **Key and index.** `FindImage(ImageDesc)` (`RC/textureCache.cpp:1323-1440`) takes `m_lock`, collects every image overlapping `[address, address+size)` through `ImagePageTable = MultiLevelPageTable<Bucket,20,44,14>` (1 MiB pages; a 64-byte bucket with 3 inline `{address,size,id}` entries; `textureCache.h:131-146`, `:189-227`) and picks the first with `SameBacking` (`:159-194`): same address, byte size, extent, cached levels/layers ≥ requested, samples, bytes/block, tile mode, colour transform, compatible pixel format and type. Stencil/depth aliasing special case at `:1340-1350`. `desc.stamp = m_resolve_cache.Stamp(...)` (`:1358`).
- **Overlap and alias resolution.** No exact match → `ResolveOverlap` per candidate (`:795-915`): block-compressed vs raw alias retirement with publish (`BcAlias`), depth overlap, same-address layout mismatch (the old image is freed only when unused for > 16 ticks, `NumFramesBeforeRemoval=16`, `:36`, `:814`), `ExpandImage` cases (`:917-933`: copy old contents into a larger new image on the GPU, free the old), sub-resource views, mip copy into a merged image (`CopyImageMip`). Unresolvable equal-address overlap is an `EXIT` (`:885-893`). Images with fewer levels/layers than requested are freed and recreated (`:1403-1406`). A new image: `InsertImage` → `Image` constructor (VMA image, `m_cpu_dirty = true` for uncompressed, `image.cpp:687-688`) → `RegisterImage` (page-table entries per 1 MiB page, atomic counts, `m_resolve_cache.Invalidate()`, `:246-266`); marked buffer-modified when the buffer cache holds GPU-dirty bytes there (`:1411-1414`).
- **Upload and state.** `FindTexture/FindRenderTarget/FindDepthTarget` take `m_lock` and call `RefreshImage` (`:1236-1258`): `TrackImage` (write-watch the image range, a `VirtualProtect`), resolve a maybe-dirty image by hashing its edge bytes, and if `IsBufferModified() || IsDefinitelyCpuDirty()` call `InitializeImage` (obtain source bytes per the copy table, `UploadImage`, `ClearBufferModified`, `RefreshComplete`). The whole image (all mips and layers) is re-uploaded each time; there is no dirty rectangle. `UploadImage` (`:950-1010`): colour → `TileManager::Detile` then `info.BufferCopies` (one region per mip) → one `copyBufferToImage`; depth → same plus a D16→D32 promotion compute (`ConvertD16`) when the host depth is 32-bit (`:981-1006`). Counter `TextureUploadBytes` (`:963`, `:1009`).
- **Detiling and format conversion** are GPU compute, not CPU: `TileManager::Detile` → `Prepare` (`R/image/tiler.cpp:81-205`: validates, fills a `TilingParams` header and one 48-byte `Mip` record per level, copies them into the 64 MiB stream buffer) → `Record` (`:245-308`: 3 buffer barriers, push descriptors, `dispatch` of ceil(texels/64) groups, post barrier). Pipelines are created lazily per (direction, tile family, bytes/element) with specialisation constants (`:207-224`; 9 families), so the first use of a combination compiles a pipeline. Output goes to one of two device-local scratch buffers, reallocated to the exact (4-aligned) size whenever a bigger image arrives, the old one freed via `DeferOperation` (`:352-365`; no growth factor). Colour transforms (`SwapBgra16`, `Reverse10_11_11`, `Rotate2_10_10_10`, `:529-596`) are further compute passes. `src/graphics/guest_gpu/tile.cpp` computes layouts and sizes only (`TileGetTextureBlockLayout` `:239`, `TileGetTextureSize` `:974`, `TileGetTexturePitch` `:1058`, `TileGetDepthSize` `:843`).
- **Invalidation.** CPU writes: fault path step 5. GPU-ordered writes and CP fills mark overlapping images buffer-modified so they reload from the buffer (`textureCache.cpp:1989-2014`; `FillBuffer`/`CopyBuffer` call these, `bufferCache.cpp:843`, `:876`). Slot reuse: `DeleteImage` unregisters at once and erases the slot in a deferred operation once the GPU tick completed (`:291-318`).
- **GC** (`RunGarbageCollector`, `:2230-2309`, once per frame): images are LRU by `m_gc_tick`. The trigger starts at 0 (`textureCache.h:317`) and with memory reporting is `(budget - min(budget, 8 GiB)) / 2` (constructor), so with a budget ≤ 8 GiB the trigger is 0, the early return never happens and every frame deletes images idle for more than 16 ticks (up to 10 per pass); age 16 ticks (80 under pressure ≥ 1.5 GiB default, 160 critical ≥ 3 GiB), 10/20/40 deletions per pass; resident-heap images are skipped; GPU-written images are evicted only under pressure and after `DownloadImageMemory` succeeds, then the GPU thread waits for the batch and calls `AdoptGuestMemory` (`:2296-2308`).
- **Read-back of GPU-written images**: `m_download_images` is filled by storage binds (`TrackImageDownload`, `:445-456`; first GPU write since CPU write, `:1491-1509`) and drained by `ProcessDownloadImages`/`WriteBackImages` (`:2311-2332`); all gated by the three config flags (default off). `DownloadImageMemory` can copy guest bytes with `m_lock` released (`:1910-1923`). With storage read-back, guest access to the pages waits for the data (`m_write_backs`, `WriteBackTick`).
- **Samplers**: `SamplerCache` is an unlocked `unordered_map` created on the main thread (constructor asserts main thread; `GetSampler`, `samplerCache.cpp:17`): key = 4 sampler words + integer-border flag; one `vkCreateSampler` per new key.
- Render-target specifics (colour/depth targets, load/store, layouts, resolves) are in [GPU.md](GPU.md); the image heap in [GRAPHICS_PIPELINE.md](GRAPHICS_PIPELINE.md).

## Stream and staging buffers

- `m_staging_buffer` 512 MiB upload ring; `m_stream_buffer` 64 MiB (device-preferred, host-visible), also used for tiler parameters, `flattened_srt` and `shader_data` uploads (`NativeUpload`, 256-byte aligned, `R/descriptors.cpp:743-749`) and index-buffer expansion; `m_download_buffer` 64 MiB (`RC/bufferCache.cpp:279-282`).
- `StreamBuffer::Map(size, alignment, allow_wait)`; on ring wrap with `allow_wait` it waits for the tick of earlier users of the region (`RC/streamBuffer.cpp:325-345`).
- Small CPU-written ranges bypass the cache buffer (stream-copy path above). The image heap uploads dirty slot ranges through the stream buffer and `CopyFrom` ([GRAPHICS_PIPELINE.md](GRAPHICS_PIPELINE.md)).

## Allocator

- VMA with `BUFFER_DEVICE_ADDRESS_BIT` (plus `EXT_MEMORY_BUDGET_BIT` when the extension is enabled); no custom pools or block-size settings (`HG/vma.cpp:77-103`). Images: `VMA_MEMORY_USAGE_AUTO_PREFER_DEVICE` + `WITHIN_BUDGET_BIT` (`:204-251`). Buffers are created elsewhere (cache `CreateBuffer`).
- **Image backing reuse**: freed optimal-tiling images with no pNext are kept in a pool (limit 128 MiB, entries older than 2 s evicted) and reused when `flags, type, format, extent, mips, layers, samples, usage` match (`HG/vma.cpp:32-73`, `:204-280`). A code comment says it exists for surfaces used alternately as depth and colour whose creation and free "is slow" (`:32-35`).
  - **Contradiction settled.** One study could not see an image-backing pool in the files it read (`Image::~Image` → `GraphicContext::DeleteImage`, not read); another documents it at `vma.cpp`. The source file shows it; the pool exists.
- The command recorder is installed before the allocator, so VMA destroy/free calls go through recorder waiting stubs (each is a recorder drain; [GPU.md](GPU.md)).
- Descriptor pools, command pools and the image heap have their own allocators ([GPU.md](GPU.md), [GRAPHICS_PIPELINE.md](GRAPHICS_PIPELINE.md)).

## Cost model per event

Reads of code, not measurements.

| # | Event | Work |
|---|---|---|
| 1 | Guest write to a watched (CPU-clean) page | One OS exception round trip on the faulting thread; `IsMapped` shared lock; region spin lock; bit ops; one protection change (`VirtualProtect` through `g_memory_state_mutex`); generation bump; `m_bda_sync_mutex` + a `std::map` node in `m_bda_sync`; texture pre-check (atomics). If an image sits on the page: texture spin lock, whole-image untrack (one or more `VirtualProtect`), `MarkCpuDirty`. If the page is GPU-dirty instead: also a `SendCommandSync` stall until the GPU thread's current packet ends, a barrier plus 512 KiB-window download and a GPU wait. Later, on the next use: re-watch (second `VirtualProtect`) and re-upload. |
| 2 | Draw binds an unchanged buffer | Memo hit (default; host view off): hash, one slot compare, `RegionGenerations` loop (one atomic load per 4 MiB region touched plus exact-hot test), LRU touch, tick stores. Host view on, sticky mode or texel binding: no `ObtainBuffer` memo; `FindBuffer` + `SynchronizeBuffer`, which still has the `UploadMemo` (cheap compare) and then `UploadCopies` returning early with no copies; written ranges additionally do `RangeSet::Add`, 8× `Subtract` on colour-metadata sets and `NoteReadbackWrite`. |
| 3 | Draw binds a buffer rewritten since last use | ≤ 16 KiB and not GPU-modified: memcpy to the stream ring per draw window (no re-watch). Otherwise dirty pages: spin lock, re-watch (protect call), memcpy to staging (+ non-coherent flush), `vkCmdCopyBuffer`; every `UploadCopies` does `EndRendering()` and two global memory barriers (`eAllCommands` ↔ `eTransfer`, `bufferCache.cpp:604-624`). Written ranges hold the region lock during this and are marked GPU-dirty (no access) afterwards. |
| 4 | Texture bound for the first time | `FindImage` (page-table walk over every 1 MiB page of the image, candidate compare, possible alias/expand GPU copies), VMA image creation, registration (+ `ResolveCache::Invalidate`), `TrackImage` protection call, `ObtainBufferForImage` (memcpy of the whole image to staging, or buffer sync), params copy to the stream ring, lazily created detile pipeline on first use of that family, compute dispatch with 3 barriers, `copyBufferToImage` with barriers, later `FindView` (not read). All under `m_lock`. |
| 5 | Texture rewritten by the CPU every frame | One fault per frame per image (the first overlapping write untracks all pages); the next use re-tracks and re-reads the whole image (staging memcpy or buffer sync + detile compute + copy): cost proportional to the full image, plus scratch growth if sizes vary. Neighbours sharing a page pay a hash of up to two edge pages each. |
